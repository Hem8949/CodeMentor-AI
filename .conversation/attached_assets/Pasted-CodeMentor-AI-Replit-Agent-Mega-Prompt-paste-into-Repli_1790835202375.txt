CodeMentor AI — Replit Agent Mega-Prompt (paste into Replit Agent)
Build a complete full-stack web application called CodeMentor AI — Personal Coding Mentor (hackathon theme: Personalized AI Experiences).
The problem
Beginners learning to code get generic help (Stack Overflow, raw AI chats) that assumes too much knowledge. They drown in jargon, copy code they don't understand, and repeat the same mistakes.
The solution
A personal AI coding mentor that adapts to each learner's skill level, language, and mistakes — it coaches instead of handing over answers.
Tech stack (strict)
Frontend: React 18 + Vite + React Router v6 + Tailwind CSS + Axios + Recharts
Backend: Node.js + Express.js + JWT authentication + bcrypt password hashing + Zod validation
Database: PostgreSQL (use Replit's built-in PostgreSQL database)
AI: Google Gemini API via REST (model gemini-3.8-flash; if unavailable use the current Gemini flash model). The GEMINI_API_KEY lives ONLY in backend environment variables (Replit Secrets) — never expose it to the frontend.
Secrets needed: GEMINI_API_KEY, JWT_SECRET, DATABASE_URL (ask me to add them in Replit Secrets if missing)

The AI mentor brain (critical — implement exactly)
Every mentor/doctor request flows: Frontend → Express backend → Gemini. The backend builds a system prompt containing the student's profile:
"You are CodeMentor, a personal coding mentor. Student: {skill_level} learning {language}. Recurring weak concepts: {their top mistakes}. Hints used on this problem: {n}. STRICT RULES: Do NOT praise every tiny thing — be warm but honest and direct. If the student's thinking is wrong, say clearly 'That approach won't work because...' then guide them to discover why themselves. Keep responses SHORT during problem solving — one small hint at a time, never the full path at once. Prefer this format: 🎯 What do you know? [a question checking understanding] / 💡 Hint [one small hint] / 🧠 Your turn [what they should try next]. Only increase help if they remain stuck. NEVER reveal the full solution unless explicitly asked via Show Solution. Your goal: make them able to say 'Give me a problem. I can figure out how to start.' When they solve something, offer a slightly harder variation. Adapt vocabulary and depth to a {skill_level}."
Per-button behavior: hint → exactly one small hint; explain → the concept with a simple real-life analogy; debug → do NOT rewrite their code, guide them to find the bug themselves; review → judge the approach and time complexity, suggest direction without giving code; similar → invent a brand-new similar practice problem (title + description + starter code); solution → full solution explaining WHY each part works; improve (doctor) → before/after code with why each change is better.
After every mentor reply, extract the weak concepts (e.g. "loops", "recursion") and store/increment them per user in a weaknesses table — this powers the "Your Weak Spots" chart and future personalization.
Database tables
users(id, email unique, password_hash, display_name, skill_level, preferred_language, created_at); problems(id, title, description, language, difficulty, starter_code); attempts(id, user_id, problem_id nullable, language, code, output, status [in_progress|solved|stuck], hints_used, created_at, updated_at); weaknesses(id, user_id, concept, count, updated_at, unique(user_id, concept)).
Seed 6 JavaScript problems: Reverse a String (easy), FizzBuzz (easy), Find Largest Number (easy), Palindrome Checker (medium), Two Sum (medium), Flatten Nested Array (hard) — each with a 1–2 sentence description including an example, plus starter code.
API (Express, all under /api; JWT required except /api/health and auth routes)
POST /api/auth/register and POST /api/auth/login → {token, user}; GET /api/profile and PUT /api/profile; GET /api/problems?difficulty= and GET /api/problems/:id; POST /api/attempts, PUT /api/attempts/:id, GET /api/attempts; POST /api/mentor {mode, problem_id?, attempt_id?, code?, language?, user_text?} → {reply, weak_concepts}; POST /api/doctor {mode: debug|improve, code, language?, error?} → {reply, weak_concepts}; GET /api/dashboard → {attempted, solved, solve_rate, avg_hints, top_weaknesses, recent_attempts, completion_pct}.
